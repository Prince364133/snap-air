# Production-readiness audit — 2026-11-16

Scope: Windows product (`engine/` Python, `app/` Electron HUD), shared `core/`, `website/`.
Out of scope: `mobile/`, `engine/src/sync/**` (other agents). Findings are ordered by
severity; `[x]` = fixed, with the change and the test that covers it. Tests live in
`engine/tests/test_audit.py` unless named otherwise.

Summary: **2 Critical, 9 High, 12 Medium, 9 Low** (32). 27 fixed, 5 left as owner
decisions / follow-ups (bottom of this file).

## Critical

- [x] **A-01 Test suite not hermetic: live Ollama, real `%APPDATA%`, order-dependent.**
  `tests/test_android.py:test_meeting_notes_from_phone_speech` (and the reminder test) called a
  locally running Ollama and timed out; six modules overwrote `SNAP_AIR_DATA` at import time so
  the last-imported one won (`test_v3 → test_life` broke `test_key_is_encrypted_at_rest`);
  `src/platform/android.py:init()` points `SNAP_AIR_DATA` at its folder for the whole process;
  `src/config.py` fixed `SETTINGS_PATH` at import, so `import main` in tests used the **user's
  real settings.json**. Baseline: 254 tests, 1 failure + 1 error.
  Fix: `tests/_env.py` (loaded by `tests/__init__.py` before anything from `src/`): temp data and
  settings dirs, sockets refused except loopback, the Ollama port refused even on loopback,
  `_ollama_exe` stubbed so `ollama serve` is never spawned. Per-module folders via
  `setUpModule, tearDownModule = _env.module_data_dir()`, per-test via `_env.isolated_data(self)`;
  `test_android` saves/restores both env vars; `Settings()` resolves its path when created
  (`config.settings_path()`). Tests: `HermeticEnvTests`, `SettingsTests.test_path_is_resolved_when_created`.
- [x] **A-02 AI-chosen desktop commands could run code without asking (prompt injection).**
  `src/brain/assistant.py:_run_tool("desktop")` only asked for confirmation for
  close/lock/shutdown/delete. Untrusted text reaches the model's context (recorded video
  transcript, learned memories), and the model's `desktop` tool can say "run my project",
  "git pull", "open a terminal", "type … and press enter".
  Fix (data, both runtimes): `core/intents/en.json` `assistant_risky` gains `en_exec`
  (run/start project|app|server|script, git, terminal/powershell/cmd, `type …`,
  send/submit/pay/buy). The user's own direct commands are parsed before the model and are
  unaffected. Tests: `AiCommandConfirmTests`, conformance `yes_no.050–058`.

## High

- [x] **A-03 Settings stored floats as strings; `bool("false")` was True; unsynchronised writes.**
  `config.Settings.update` sent every non-bool/int/list/dict default through `str()`, so
  `tts_speed`, `end_of_speech_s`, `continuation_wait_s` became `"1.2"` — and the synced
  settings profile (`continuation_wait_s` is a `number` in `core/schemas/settings_profile`)
  would hand phones a string. Concurrent updates from HUD / voice / sync threads mutated and
  dumped the same dict unlocked. Fix: `config.coerce()` (finite floats, `"false"/"off"/"0"` →
  False, wrong types rejected), `load()` repairs values older builds wrote as text, an RLock
  around apply+save, listeners called outside the lock. Tests: `SettingsTests` (6).
- [x] **A-04 `open_editor` shell injection and dead fallback.** `OSActions.open_editor` ran
  `subprocess.Popen(f'{exe} "{path}"', shell=True)`; a project folder containing `"` or `&`
  ran commands, and with `shell=True` a missing editor never raised, so the Explorer fallback
  never happened. Fix: `shutil.which` + argument list, no shell; batch launchers (`code.cmd`)
  are skipped when the path holds cmd metacharacters; editor list moved to app.json
  `dev.editor_commands`. Tests: `OpenEditorTests` (3).
- [x] **A-05 WebSocket token inherited by every program Snapy starts.** Electron passes the token
  in `SNAPY_WS_TOKEN`; the engine kept it in `os.environ`, so the terminal for "run my project",
  the user's dev server and the editor all inherited it (any npm script could then drive Snapy).
  Fix: `auth.load_or_create_token` pops it. Test: `TokenEnvTests`.
- [x] **A-06 Truncated model downloads accepted as installed.** `Setup.fetch` renamed `.part` →
  final whenever `iter_content` ended, including a cleanly closed connection mid-file; a later
  `whisper_ready()` only checks existence, so speech stayed broken. A complete `.part` (crash
  before rename) got HTTP 416 four times and failed setup. Piper and Kokoro downloads in
  `piper_voice.download` / `tts._download` had no size check at all. Fix: size verified against
  HEAD/Content-Length (skipped for compressed transfers), resume on mismatch, complete/oversized
  `.part` handled before requesting; shared `setup_assets.download_file()` used by both voice
  paths. Tests: `DownloadTests` (3).
- [x] **A-07 Ollama installer executed without integrity checks from a predictable path.**
  `main.install_ollama` wrote `%TEMP%\OllamaSetup.exe` (pre-plantable / swappable), ran it even if
  the body was short, ignored the exit code, and two triggers could race. Fix: private
  `mkdtemp` folder removed afterwards, `setup_assets.verify_installer` (size + Authenticode
  `Valid` + signer contains app.json `ollama.installer_signer`; path passed via env, not the
  command text), non-zero exit = error, a lock around the status check. Tests:
  `test_installer_must_be_complete_and_signed`, `EngineWiringTests.test_installer_runs_only_after_verification`.
  Decision noted below (D-1).
- [x] **A-08 "Delete all my data" left personal data behind.** `main.delete_all_data` kept
  `export-*.json` (a full copy of memories, tasks and notes), parked work contexts, the
  in-memory conversation and the nudge history. Fix: all removed. Test:
  `EngineWiringTests.test_delete_all_data_removes_exports_and_contexts`.
- [x] **A-09 Electron: no CSP, IPC accepted from any sender.** `app/index.html` had no
  Content-Security-Policy; only `ws-token` checked the sender. Fix: strict CSP meta
  (`script-src 'self'`, `connect-src ws://localhost:* ws://127.0.0.1:*`, no objects/forms/base);
  every IPC channel goes through `fromHud()` (main frame of our window, `file://`);
  `web-contents-created` denies navigation, new windows and `<webview>` for any contents;
  `open-external` parses the URL and allows only http(s). Verified with `node --check`;
  renderer uses no inline scripts/handlers (h() uses addEventListener).
- [x] **C-01 Memory rule category `work` not in the schema enum** (from the Dart-runtime agent).
  `core/intents/en.json` role/company rules emitted `work`; both stores silently saved `fact`.
  Decision: rules emit `fact` (identical stored result, no enum change, no cross-version sync
  break). Conformance `memory.json` updated; test `CoreDataTests.test_memory_rule_categories_are_in_the_schema_enum`
  checks every rule against the enum.
- [x] **C-04 "write me a poem about rain" was typed instead of answered** (phone intent
  `type.text`, and the same bug in the Windows grammar). Fix: `write` only types when not
  followed by me/us/him/her/them/a/an/some/my/about, unless the phrase targets a field/box/bar;
  the Windows `write` command now asks the same core rule (`phone_intents.parse`). Tests:
  conformance `phone_intents` +7 cases (4 negative, 3 positive),
  `CoreDataTests.test_desktop_write_leaves_creative_requests_to_the_ai`.

## Security assessment (summary)

- WebSocket: token (32 bytes, constant-time compare, bytes not str) + Origin allow-list checked in
  the handshake before any message; the token is never logged (refusals log reason + origin only),
  never in a page URL, no longer inherited by child processes. Bypass attempts tested in
  `test_security.py` (no/wrong token, browser origins with a valid token, non-ASCII token).
- Command execution: no `shell=True` left in `engine/src` (only `taskkill`/PowerShell with fixed
  argument lists). `run_terminal` executes the configured/detected project command (user setting
  via the authenticated HUD; not in the synced settings profile, so a paired phone can't set it).
  The phone's `link` command is limited to http(s) by `src/sync/session.validate_command`.
- Paths: downloads use names from app.json/catalogues, never user text; voice ids are matched
  against `PIPER_CATALOG`. No zip extraction in the engine.
- Secrets: DPAPI (CurrentUser, UI forbidden); decrypt failures recorded without the value.
- LLM: secondary calls with page/clipboard/web text use `chat_text` (no tools); tool calls that
  run code, type, send or pay need a spoken/typed yes (A-02).
- Electron: contextIsolation, sandbox, no nodeIntegration, CSP, navigation/new-window/webview
  denied for all contents, IPC sender-checked, preload exposes an allow-list.

## Decisions for the owner

- **D-1** The Ollama installer must be Authenticode-`Valid` and signed by a subject containing
  `Ollama` (`ollama.require_signature`, `ollama.installer_signer` in app.json). If Ollama ever
  ships unsigned or changes its legal name, first-run setup shows "signature is not valid" —
  set `require_signature: false` in `%APPDATA%\SnapAir\app.json` as an escape hatch.
- **D-2** Should short-video counting be opt-in during onboarding (A-19)? Left on, as built.
- **D-3** AI-initiated "type …" now asks first (A-02). If that feels slow for dictation through
  the model, narrow `en_exec` to code-running commands only.
- **D-4** `engine/src/platform/android.py` + `tests/test_android.py`: the Android app no longer
  embeds Python (Chaquopy removed). They still pass and exercise the shared Python brain in
  "phone mode", but now duplicate `mobile/lib/core_runtime` + conformance. Proposal (not done):
  remove both once the Dart conformance run is in CI, keeping `phone_intents.py` (Windows uses
  it for the `write` guard).
- **D-5** Memory category `work` → `fact` (C-01); transcript = array (C-02). Both documented in
  `core/README.md` §7.
